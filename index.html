Abstract

Game engines can produce realistic virtual experiences by simulating real life physics. This article aims to explore the modelling of forces, motion and the interactions of objects using physics engines. Core concepts such as collisions detection and numerical integration, which allow engines to determine how objects touch and move, will be investigated. These simulation techniques focus on stability and performance over accuracy whilst still providing a realistic result to the players. The limitations of game physics and how advancements in hardware will improve them will also be explored.

Introduction

Modern video games frequently use real world physics in their core mechanics. For example when a character moves up a slope or jumps from a platform to another, the game engine will calculate the motion to present a natural feeling result to the player. Although game engines do not replicate real world physics completely accurately, as this is highly demanding, they present a motion which feels correct to the player (Barraff, 1977).

Popular game engines such as Unity and Source Engine create and use their own physics libraries. For example the Source Physics System (Valve, 2023). The benefit of using these libraries is that the developers can create believable scenarios whilst also being able to control the computational costs (Nvidia, 2023).

How games engines simulate physics

Game engines utilise cyclic loops known as simulation loops (Baraff, 1977). These loops calculate interactions of objects and run continuously allowing a game to execute events endlessly.

Collision Detection

Within the simulation loop, one of the most important tasks is collision detection, which is done using a two stage approach. The Broad phase identifies and ignores objects that are too far apart using simple shapes or hitboxes (Baraff, 1977). Following on, the narrow phase priorities accuracy and uses algorithms such as Separating Axis Theorem or Gilebrt-Johnson-Keerthi methods to detect any collisions and the level of penetration (Baraff, 1977).

Once a collision has been identified, the engine will create appropriate and realistic movements to portray the action, in a way that is stable and relates to the game.

Key techniques used in physics engines

Numerical Integration and Motion

Mathematicians use calculus to calculate motion however games tend to use numerical integration to find an approximation of these calculations as they do not require exact solutions. One method used is Eulers integration which examines the slopes at a point to estimate the next, meaning it can become unreliable when objects are moving at high speeds or with great force. Semi Implicit Euler, is used to counter this as it updates the velocity before the position. Another method used by game engines is Verlet integration as it outputs more smooth and stable motions then Euler integration and it is commonly used for cloth or particle systems within games (Bourg and Seemann, 2001). These methods allow for the realistic movements we see in video games whilst maintaining stability.

Rigid Body Modelling

Objects which do not need to bend or change shape are labelled as rigid bodies, allowing for calculations to be much easier. However, when completing calculations relating objects such as fluids or cloths the engine will need to use techniques such as Position based dynamics (Macklin et al, 2014). This method updates the position of the vertices of the object rather then directly applying a force to it which makes it efficient and suitable for video games as it is fast and stable.

Limitations and Future Developments

Realism and performance will always have to be balanced when it comes to the physics of a game, leading to many limitations:

Floating Point errors: Extremely precise numbers cannot be stored on computers, leading to rounding errors which can cause irregular movements in the objects such as drifting or jitters.

Performance Issues: Since games need to ensure they have good performance for players to run them at stable FPS and without crashes, algorithms must be simplified to allow for clean simulation of multiple objects (Nvidia, 2023).

Multiplayer Games: Players may see different things to others as the game will be processed differently according to their devices power, leading to competitive disadvantage in online games. To add to this, games commonly use predictions to counter this which then leads to even more issues as the players ping can affect the accuracy of these predictions.

Improper Collision Detection: Games tend to use htiboxes to define the regions where players can be damaged. Due to the fact that hitboxes are made of simple shapes such as boxes, spheres and cylinders this can lead to body parts clipping through walls or players may notice that their bullets are hitting the enemy models but not registering any damage. This can lead to a competitive disadvantage for players and ruin their immersion within the game.

Tunnelling: Games that do not have continuous collision detection due to its expense may experience objects phasing through walls when they move at insanely high speeds.

However, as technology advances so will the capability of game engines. With the increase in GPU technology an increasing number of objects can be simulated with more realistic behaviours then before. Adding to this, machine learning techniques can accurately predict movements without the developers having to define parameters.

Conclusion

Game engines simulate physics by creating a balance between realism and performance by simplifying algorithms and models to present a believable simulation to players. Although the current capability of these engines is not enough to produce perfect versions of the real worlds physics, the progression of technology will allow these simulations to move closer and closer to it whilst still maintaining appropriate performance for players to enjoy the games.
